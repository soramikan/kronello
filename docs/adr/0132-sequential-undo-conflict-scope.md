# ADR-0132: Undo イベントの競合範囲を打ち消し対象に限定する

- 状態: 採用
- 日付: 2026-10-08
- 部分置換: [ADR-0026](0026-selective-undo.md) の「対象イベントより後の、取り消されていないイベントが同じキーに触れていれば `UNDO_CONFLICT` で拒否する」の判定対象のみ

## 置換範囲

ADR-0026 の Undo は新規イベントとして発行する方式、session・changed keys・逆操作の永続化、`UNDO_CONFLICT` の拒否と競合情報の同梱、GUI の session 内 Undo 範囲、履歴からの event ID 指定取り消しは維持する。変更は「target より後で active な同キーイベント」に数える対象だけに限定する。

## 背景

ADR-0026 は Undo 自体もイベントであり、取り消されない限り同じキーの後続イベントとして競合判定に入ると読める。GUI 監査でこの厳密解釈の問題が実機で確認された。forward な編集 A → B のあと B を取り消すと、undo イベント U(B) が同じキーの active な後続イベントとなり、A の取り消しが永久に拒否される。U(B) を取り消せば B が復帰して依然としてブロックするため、A は二度と取り消せない。U(B) が消すものは B の変更だけであり、A より後の実質的な書き込みではないのに、逐次 Undo が途中で止まる。

## 決定

Undo イベントが打ち消した対象が「target より後の forward 編集」(`undo_of` が後続イベントを指し、そのイベントが Undo イベントでない) である場合、その Undo イベントは競合判定の「後続の書き込み」から除外する。その Undo は対象キーを target 直後の状態へ戻しただけであり、新しい独立した変更ではないためである。

Undo イベントが打ち消した対象が target より前のイベント、または別の Undo イベント（Redo）の場合は通常どおり競合対象とする。Redo は後続の実質的な書き込みであり、それを経ずに先行イベントを取り消すと履歴の意味が壊れるためである。forward 編集が同じキーに後続して存在する場合の拒否も変えない。

## 影響

- GUI の「取り消す」が直前の編集から順に遡れる。ADR-0026 の目的である「他者の変更を黙って消さない」は維持される。B を取り消したあと A を取り消しても、U(B) の記録と逆操作は残り、U(B) の取り消し（B の Redo）は今度は A の取り消しイベントと競合するため順序が強制される。
- `UNDO_CONFLICT` の `conflicts` に Undo イベントが列挙されるのは、それが forward 編集の打ち消しではない場合に限られる。
- `kronello-service` の `validate_undo` と回帰テスト `undo_of_later_edit_does_not_block_undoing_earlier_edit` がこの意味を固定する。
