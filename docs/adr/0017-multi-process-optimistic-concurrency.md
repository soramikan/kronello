# ADR-0017: 複数プロセスからの編集を楽観的 revision 検証で直列化する

- 状態: 採用
- 日付: 2026-10-02

## 背景

ADR-0014 により GUI・CLI・MCP は別プロセスになる。GUI で開いているプロジェクトをエージェントが CLI / MCP から編集し、その結果を GUI で確認する使い方を成立させたい。

## 決定

- 複数のプロセスが同じ `.kronello` を同時に開いてよい。
- 書き込みは排他トランザクション内で `base_revision` を現在の revision と照合し、一致しなければ競合として拒否する。
- `idempotency_key` と適用結果を `.kronello` 内に保存し、別プロセスからの再送にも同一結果を返す。
- 各プロセスは外部からの revision 変化を検知し、以降のイベントを読んでスナップショットを更新する。GUI は再読込する。

## 影響

- 検知が遅れても、古い revision に基づく書き込みは必ず拒否されるため、黙った上書きは起こらない。
- 「単一 writer」はプロセス単位ではなく、書き込みトランザクション単位の性質になる。
- ID は各プロセスが衝突なく生成できる形式でなければならない。
- Undo と外部変更の相互作用を決める必要がある（ADR-0026 で決定）。
- 検討した代替案: GUI が内蔵サーバーとなり CLI / MCP が委譲する方式、排他ロックで同時編集を禁止する方式。
