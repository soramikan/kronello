# ADR-0024: 作業用色空間は Sequence ごとに選択し、既定を線形 Rec.709 とする

- 状態: 採用
- 日付: 2026-10-02

## 背景

v0.2 仕様は「明示した作業用線形空間」とだけ定め、既定値を決めていなかった。テンプレートの色入力（`#F59E0B` など）をどの色空間の値として解釈するかも未定だった。M0 の色・alpha 規約（ARC-001、GPU-001）に必要な決定である。

主な用途は Web・配信向けの SDR であり、HDR は M4 で品質を確立する。

## 決定

- 作業用色空間は Sequence ごとに選択する（`Sequence.working_space`）。
- 初期実装の選択肢は線形 Rec.709（sRGB 原色、D65）と線形 Rec.2020（D65）の 2 つ。
- 新規 Sequence の既定は線形 Rec.709。HDR / 広色域の出力プロファイルを選んだ Sequence は線形 Rec.2020 を既定とする。
- 中間画像は RGBA16F とし、範囲外の値を出力変換まで保持する。
- 色空間の指定がない色入力は sRGB（非線形符号化）として解釈する。保存時は `{space, components}` の明示表現へ正規化し、評価時に作業用色空間へ変換する。
- Composition は固有の作業用色空間を持たず、配置先の Sequence の作業用色空間で評価する。
- 作業用色空間は `color_pipeline_id` とキャッシュキーに含める。

## 影響

- SDR だけの作品では色域変換が最小になり、検証しやすい。
- 色入力は Web やデザインツールの色と見た目が一致し、作業用色空間を変えても意味が変わらない。
- 同じ Composition を作業用色空間の違う Sequence に配置できる。2 つの空間は線形変換の関係にあるため、線形補間と加算的な合成の結果は一致するが、非線形な blend mode や切り捨てを伴う処理では差が出うる。
- ACEScg は初期の選択肢に含めない。外部レンダー連携（M6）で必要になれば選択肢として追加する。
- HDR の基準白レベル、表示変換、トーンマッピング、色域マッピングは未決（OQ-18）。
- 検討した代替案: 常に線形 Rec.2020、ACEScg、線形 Rec.709 に固定。色入力については、タグ必須、作業用色空間の値として解釈。
