# ADR-0130: 書き出しプリセット・バッチキュー・ウォッチフォルダ

- 状態: 採用
- 日付: 2026-10-08

## 背景

FLOW-003 は書き出しプリセット・バッチキュー・
ウォッチフォルダを要求する。プリセットの保存先・
バッチの実行意味・監視の実装形態を決める。

## 決定

- プリセットは `Project.export_presets: Vec<ExportPreset>`
  として versioned で作品に保存する。name・JobRequest 相当の
  設定・目的ファイル形式を含む。個人環境の既定は
  FLOW-001 と同じユーザー環境側とし、こちらは作品内容として
  扱う共有プリセット。
- バッチキューは `export.batch` で複数の job 投入を 1 つの
  共有編集として表す。各 job は既存の JOB-002 系 worker が
  実行し、投入自体は冪等キーで重複を拒否する。実行順序・
  失敗時の継続可否は request パラメータとする。
- ウォッチフォルダは service の常駐機能とせず、CLI の
  `kronello watch` を long-running プロセスとして実装する。
  指定ディレクトリの新規ファイルを検出し、設定済み
  プリセットで `export.batch` 相当の job を submit する。
  検出ポーリング間隔・再投入抑止（hash + size 安定確認）は
  CLI 側で決定的に行う。
- 監視による失敗・投入失敗はログと終了コードで報告し、
  黙って drop しない。
