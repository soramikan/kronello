# ADR-0054: GUI の見た目を全 OS 共通のデザインシステムで定める

- 状態: 採用
- 日付: 2026-10-04

## 背景

ADR-0014 / 0032 で GUI を OS ごとのネイティブフレームワーク（macOS は SwiftUI / AppKit、Windows は WinUI 3、Linux は GTK4）で実装すると決めたが、見た目（色、書体、アイコン、部品の寸法と状態）は決めていなかった。M3 で macOS 版の GUI に着手する前に、後から作る Windows / Linux 版と揃う基準が必要になる。動画編集では UI の色が素材の色の判断を妨げないことも求められる。

## 決定

- 見た目は全 OS で同一にする。macOS の慣習（22px のコントロール、控えめな角丸、ダイアログのボタン順）を基準に、各フレームワークの標準コントロールを共通の見た目にスタイルして使う。OS 標準の見た目には委ねない。修飾キーの表記だけは OS に合わせる（⌘ ↔ Ctrl、⌥ ↔ Alt）。
- OS が描くもの（macOS のメニューバー、ファイルダイアログ、ウインドウの枠、通知）は OS のものを使う。IME・アクセシビリティ・キーボード操作は各フレームワークの仕組みを使う。
- テーマは Dark と Light の 2 つ。既定は Dark とし、システムの外観には追従しない。
- 強い色の役割を 3 つに限る: 琥珀（`accent`）= 「今」とブランド（再生ヘッド、現在時刻、主ボタン）、青（`selection`）= 選択（選択中の要素、フォーカス、メニューの現在項目、チェックのオン）、赤（`danger`）= 型付きエラー。素材とクリップの種類は控えめな種類の色（`kind-*`）でアイコンと細い下線だけを塗る。状態は色だけで伝えず、形・アイコン・文言を添える。
- 書体は Noto Sans JP（UI）と Noto Sans Mono（数値・タイムコード）をアプリに同梱する（SIL OFL）。システムフォントは使わない。
- アイコンは Lucide（ISC、一部 MIT）だけを使う。SF Symbols は Apple 以外で使えないため採用しない。
- 値の正本は [design-system/tokens.json](../design-system/tokens.json)、規則と部品仕様の正本は [docs/design-system/](../design-system/README.md) とする。各実装はトークン名を定数名として写す。

## 影響

- OS ごとの見た目の差を実装で吸収する必要があり、標準コントロールをそのまま置くより工数が増える。代わりに画面設計・スクリーンショット・説明書を 1 つにできる。
- 文字・枠・フォーカスリングは両テーマで WCAG 2 のコントラスト（文字 4.5:1、線と記号 3:1）を満たすよう値を選んだ。値を変えるときは計算し直す。
- Noto Sans JP の同梱でアプリが数 MB 大きくなる。同梱の形態（可変フォントかウェイト別か、サブセットするか）は GUI-001 で決める。
- macOS 利用者には OS 標準と少し違う見た目になる。ADR-0014 が求めた OS 標準の操作感（IME、アクセシビリティ、ショートカット、メニューバー）は維持する。ADR-0014 / 0032 の決定は変更しない。
- 字幕クリップと調整クリップの種類の色は、モデル（`SourceRef` は Asset / Composition / Generator）にまだない種類の予約枠として先に定めた。
- 検討した代替案: 各 OS の標準の見た目に従う（OS 間で画面がずれ、色の役割を保てない）、システムフォント（SF Pro は Apple 以外に配布できない）、SF Symbols（同上）。
