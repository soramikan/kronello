# ADR-0026: Undo は逆操作の発行とし、競合時は拒否する

- 状態: 採用
- 日付: 2026-10-02

## 背景

ADR-0017 により、GUI で開いているプロジェクトをエージェントが CLI / MCP から同時に編集できる。GUI の Undo が全体の履歴を巻き戻すと、利用者が意図せずエージェントの変更を取り消してしまう。逆操作情報の保存形式（STORE-001）に影響するため、Undo の意味を先に決める必要がある。

## 決定

- Undo は、対象イベントの逆操作を新しいコマンドとして発行する。revision は常に前進する。Undo 自体もイベントであり、Redo はその Undo イベントの取り消しである。
- 各イベントは、発行した session と、変更したキーの集合を記録する。値の変更は `(オブジェクト ID, Property ID)`、構造の変更は対象オブジェクトとその親コンテナの ID をキーとする。
- 対象イベントより後の、取り消されていないイベントが同じキーに触れていれば、`UNDO_CONFLICT` で拒否する。部分的な適用はしない。エラーには競合したイベントとキーを含める。
- GUI の Undo は、その GUI セッション（プロジェクトを開いてから閉じるまで）が発行したイベントだけを、新しい順に取り消す。
- CLI / MCP と GUI の履歴一覧からは、event ID を指定して `edit.undo` で取り消せる。同じ競合規則を適用する。
- イベントと逆操作情報は `.cinewright` に永続化する。

## 影響

- 他者の変更を黙って消すことがない。エージェントが別の Property を変更しただけなら、GUI の Undo はそのまま通る。
- 同じ Property を後から別の操作が変更していると Undo できない。利用者には理由と競合相手が示される。
- 式やレイアウトを経由した間接的な影響は競合判定に含めない。Undo 後の状態は通常の検証を通す。
- GUI を再起動すると Cmd+Z の対象は空になる。過去の操作は履歴一覧から event ID 指定で取り消す。
- 履歴が `.cinewright` に蓄積するため、保持期間と圧縮の方針が必要になる（OQ-19）。
- 検討した代替案: 全体で 1 本の履歴の巻き戻し、外部変更時の Undo 履歴破棄、競合時の部分適用。範囲は、永続的な操作者 ID 単位、GUI セッション内のみ。粒度は、オブジェクト単位、Composition / Sequence 単位。
