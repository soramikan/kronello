# ADR-0025: レンダージョブは切り離した worker プロセスで実行する

- 状態: 採用
- 日付: 2026-10-02

## 背景

長時間レンダーは MCP 接続や CLI の寿命に依存させない、という要件がある。一方、ADR-0014 と ADR-0017 により常駐デーモンは置かない構成になった。ジョブを誰が実行し、記録をどこに置くかを決める必要がある。

## 決定

- ジョブ 1 件につき worker プロセスを 1 つ、投入したプロセスから切り離して起動する（`cinewright worker --job <id>`）。常駐するプロセスは置かない。
- GUI・CLI・MCP のいずれから投入しても同じ仕組みを使う。投入したプロセスが終了してもジョブは続く。
- ジョブの記録（状態、進捗、成果物の場所）は、`.cinewright` の外にあるユーザーごとの状態 DB に保存する。
- 投入時に固定スナップショットを直列化して状態領域のジョブディレクトリへ保存する。worker はそれを入力とし、ジョブの進行で `.cinewright` へ書き込まない。
- 既定の同時実行は 1 ジョブ。worker は状態 DB 上の実行スロットを取得してから実行し、取得できない間は `queued` で待つ。スロット数は設定で変更できる。
- worker は定期的に heartbeat を記録する。途絶えたジョブは `interrupted` と報告し、スロットを解放する。自動では再開しない。
- プレビュー（`preview.render`）はジョブにせず、呼び出したプロセス内で実行する。

## 影響

- ジョブは「このマシンでの実行」であり、作品の内容ではない。プロジェクトを別のマシンへ移しても書き出し履歴は付いてこない。
- 進捗の更新が作品の revision や書き込みロックと競合しない。
- 投入後にプロジェクトが編集されても、ジョブは投入時点のスナップショットで完了する。
- マシンの再起動をまたいだ自動再開はしない。`interrupted` のジョブは明示的に再開する（RECOVERY-001）。
- 状態 DB とジョブディレクトリの掃除（保持期間）を決める必要がある（ADR-0034 で決定）。
- 検討した代替案: オンデマンド起動の常駐ワーカー、OS のサービス機構への登録、呼び出しプロセス内での実行。記録の置き場所は `.cinewright` 内、両方に分ける案。同時実行は無制限、資源予算ベースの許可制御。
