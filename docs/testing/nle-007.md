## Public API / schema

- wire 操作: `multicam.create`・`clip.angle_switch`（`api.rs` の registry に登録、CLI は `multicam create` / `clip angle_switch` で同一 Request を発行）。
- `MulticamCreateRequest` は `sync: timecode | audio | manual`・`angles[]`（呼び出し側が安定 `AngleId` を指定）・`reference`・`offsets` を受ける。audio 同期は 48 kHz デコード済み音声の正規化相互相関（`kronello_audio::estimate_sync_lag`）で lag を推定し、`sync_offset = audio_start(angle) - audio_start(reference) - lag` を永続化する。推定不能・音声ストリーム欠落は `MULTICAM_SYNC_FAILED` の型付きエラー。
- `ClipAngleSwitchRequest { sequence, clip, angle }` は clip の `SourceRef::Multicam` の angle のみを差し替える。配置・他クリップ・group 定義は不変。
- `schemas/project-v1.schema.json` / `schemas/api-v1.schema.json` / `GeneratedAPI.swift` を再生成。schema 番号は 1 を維持。

## 制約・既知の限界

- audio 同期の実メディア decode → 相関推定 → offset 適用の経路は、推定器が `kronello-audio` の unit test（正負 lag・silent / weak / ambiguous / overlap / bounds / budget / empty の型付き失敗）で、service 側は音声欠落時の `MULTICAM_SYNC_FAILED` と手動/timecode の e2e で検証済み。音声付き実メディアを通す `multicam.create` の e2e は A/V 同期 fixture が無いため未実施。
- GUI の実画面確認（作成シートの表示・角度ピッカーの見た目）はこの環境では未実行。`SourceMonitorTests` が実 worker 経由で操作接続を検証しており、画面確認は GUI-011 の残件と共通。
- sync_offset は有理数の Time で永続化され、浮動小数点は使わない。manual offsets は全角度分の指定を要求し、余剰キーは `INVALID_MULTICAM` で拒否する。
