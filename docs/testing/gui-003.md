render / collect の resolver は引き続き全内容 hash を検証する。既存resolverの mismatch / fallback / 再検証テストも成功した。
トップレベル registry は38操作のまま。新しい共有 variant は `clip_split`、新しいquery fieldは `asset_status`。
service error code は元から文字列の `ServiceError` であり、enum新設・operation追加はない。

## ホスト review（Dark / Light、1440×900）

1. fixtureを開き、Project / Viewer / Inspector / tracksの指定寸法、V2/V1/A1、素材種類とstream番号、
   missing.movの赤いicon/codeとclip破線を確認する。clip種類で面や文字を塗らず、selectionだけがblue。
   missingはmetadata行だけの情報から推測せずasset_status由来。現在時刻だけがamber。
2. 素材streamの行を対応trackへdragする。候補だけ追従し、releaseでrevが1増え、Undo一回で配置が戻る。
   audioをvideo trackへ置く要求は候補を出さない。overlap等の拒否はtyped error、部分的に置かない。
3. clip本体を同一track内で移動、左右6pxのhandleで内側へtrimする。候補中はCLI exportが不変、
   release一回のEvent、Undo一回。Inspector開始と尺は中立色、source開始/速度/逆再生/合成は表示のみと理由。
   lockすると編集できずproject revisionは変わらない。visibility/muteはtooltip付きdisabled。
4. B / ToolStripでbladeへ切り替え、clip内点をクリック/dragする。青いcut候補、release一回のsplit、
   左ID保持・右新ID・連続source映像、Undo一回。境界はINVALID_EDIT。linked/transitionは対応するtyped拒否。
5. clipを選択、Inspectorの「モーションで開く」とdouble-clickで参照Compositionへ移る。
   ページ移動だけではrevisionが変わらず、Editへ戻るとSequence/clip選択が残る。
6. drag中に別terminalから下のexternal moveを実行し、releaseするとREVISION_CONFLICT banner。
   破棄/再適用は明示操作だけ。自分のmove後に同じSequenceを外部moveしてUndoするとUNDO_CONFLICT Dialog。
   外部Eventはsession Undoへ加えない。読込中は中立activityとstale表示の注記、操作への応答を保つ。
7. 空白laneにfocus、V/B・Space・矢印、各Button/Timecode/AssetRow/ClipをTabで移る。
   実際にfocusしたcontrolかtracks containerにだけ2pxblue ring、他の子は光らない。
   Timecode入力中にV/Bを押してもtoolを変えない。Dark/Lightで同じ検査を繰り返す。
8. 実MetalのSequence target、resize/occlusion復帰、Full/Half/Quarter、query failureのtyped Viewer errorを確認する。
   音声clockの再生とA/V同期はAUDIO-002の統合後にその手順で確認する。
