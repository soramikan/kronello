# QA-004: 環境別 golden と Apple Silicon 校正

## 契約と手順

[ADR-0088](../adr/0088-platform-golden-baselines.md) により、同じ 40 シーンと比較版 1 (`2^-10`) を Apple Silicon Metal / Linux Vulkan / Windows Direct3D12 の個別基準へ比較する。`linux-vulkan` と `windows-dx12` の基準は下記の実測候補から明示採用済み。Linux / Windows の採用済み基準による通常比較は、公開 repository の CI 再開後に両方成功した（下記 CI 37414923914）。基準画像がない状態では比較は失敗する。

各環境で候補を生成する。`WGPU_BACKEND` は Metal=`metal`、Linux=`vulkan`、Windows=`dx12`。`KRONELLO_GOLDEN_OUTPUT` は絶対パスの新規 `target/golden/run.*/` にする。

```sh
WGPU_BACKEND=vulkan KRONELLO_GOLDEN=1 KRONELLO_GOLDEN_UPDATE=1 \
 KRONELLO_GOLDEN_OUTPUT="$PWD/target/golden/run.qa004.candidate" \
 cargo test -p kronello-gpu --test golden --locked -- --ignored --nocapture
```

40 シーン・40 frames、全画素 CPU oracle 合格と環境・画像を確認し、clean revision の候補を明示採用する。Windows は profile を `windows-dx12` にする。

```sh
python scripts/golden_adopt.py target/golden/run.qa004.candidate/candidate --profile linux-vulkan
WGPU_BACKEND=vulkan KRONELLO_GOLDEN=1 \
 KRONELLO_GOLDEN_OUTPUT="$PWD/target/golden/run.qa004.compare" \
 cargo test -p kronello-gpu --test golden --locked -- --ignored --nocapture
```

CI の `qa004-platform-golden` は両環境で候補生成と採用済み基準の比較を実行し、常に artifacts を保存する。候補の生成成功は基準比較の成功ではない。採用は自動化しない。Linux hosted runner は Mesa lavapipe を選ぶ。Windows は Direct3D12 の実際に選択された adapter を記録する。`device_type=Cpu` と `software_adapter=true` の結果は software adapter の証拠であり hardware GPU の証拠ではない。基準と比較の device class が変われば拒否する。adapter 不在は非ゼロ終了し、CPU reference に置換しない。

## M1 / M4 校正の実測

2026-10-06、基点 `572a4e80ea98a277d28eb86fc13a865cfb8a76cb` に QA-004 harness の未コミット変更を加えた状態で実行した。比較時の dirty 状態と入力・renderer / shader / oracle / lockfile の hash は provenance に記録される。基準の更新・許容誤差の拡大はしていない。

| 項目 | 既存基準 | 実測 |
|---|---|---|
| adapter | Apple M1 Metal | Apple M4 Metal |
| 機種 | MacBookPro17,1 | Mac16,10 |
| メモリ | 16 GiB | 32 GiB |
| device class | IntegratedGpu | IntegratedGpu |
| 実測 OS | 基準 environment.json | macOS 27.0.1 / 26A434 |

40 シーン、40 frames、20,950 pixels が **全件 pass**。mismatched pixels=0、最大 RGB 絶対差 `0.00048828125`（`coverage-fill-stroke`）、最大 alpha 差=0。許容誤差 `2^-10 = 0.0009765625` のまま、全画素・全成分の絶対 / 相対比較を満たした。実行 9.10 s。M1 と M4 について共通基準の妥当性を確認した範囲であり、将来の全 GPU 世代を保証するものではない。

再現コマンド:

```sh
WGPU_BACKEND=metal KRONELLO_GOLDEN=1 \
 KRONELLO_GOLDEN_OUTPUT="$PWD/target/golden/run.qa004.m4-calibration" \

```

証拠は `target/golden/run.qa004.m4-calibration/` の `report.json` / `environment.json` / `environment-diff.json` / `provenance.json` / actual と差分。ログは `/private/tmp/qa004-m4.log`。CPU adoption gate の 11 tests と Rust golden の通常 3 tests が合格した。この校正時点ではLinux / Windowsの実測・明示採用・通常比較は未確認だった。後続の採用・比較結果は以下に記録する。この時点では Windows 通常比較が未確認だった。公開 repository の CI 再開後の通常比較結果は末尾に記録する。

## M8: 56 シーンへの基準更新（FX-005 / FX-006）

FX-005 / FX-006 が 7 シーン（`fx005-chroma-key` / `fx005-chroma-key-edges` / `fx005-luma-key` / `fx006-glow` / `fx006-sharpen` / `fx006-vignette` / `fx006-corner-pin`）を追加し、カタログは 56 シーン・56 comparison frames になった。apple-silicon-metal の候補生成・CPU oracle 検証・明示採用・通常比較は lane C の revision `47ed7ec` で完了済み。linux-vulkan / windows-dx12 には基準ディレクトリが無かったため、以下の流れで採用した。

[CI 37711522980](https://github.com/soramikan/kronello/actions/runs/37711522980)（PR #12、requested head `7280548`、clean checkout は PR merge `093c89e36ef166027bdd68bac61244988f3acd83`）は両環境で 56 シーンの candidate を CPU oracle 付きで生成し、採用済み基準が無いため通常比較で失敗した。これは ADR-0088 の「基準欠落を失敗とする」ゲートの期待動作である。両 artifact の candidate は `candidate_may_be_adopted=true`・provenance `status` 空・revision `093c89e` で、56 シーン全て CPU oracle を通過していた。

merge commit `093c89e` の隔離 checkout で `golden_adopt.py` を実行し、artifact の candidate を明示採用した。

| windows-dx12 | Microsoft Basic Render Driver 10.0.26100.33438, device_type=Cpu, software_adapter | 398,893 | 56 scenes adopted |
