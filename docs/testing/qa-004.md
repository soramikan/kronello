# QA-004: 環境別 golden と Apple Silicon 校正

## 契約と手順

[ADR-0088](../adr/0088-platform-golden-baselines.md) により、同じ 40 シーンと比較版 1 (`2^-10`) を Apple Silicon Metal / Linux Vulkan / Windows Direct3D12 の個別基準へ比較する。`linux-vulkan` と `windows-dx12` の保存先は実測候補の採用待ちであり、基準画像がない状態では比較は失敗する。

各環境で候補を生成する。`WGPU_BACKEND` は Metal=`metal`、Linux=`vulkan`、Windows=`dx12`。`KRONELLO_GOLDEN_OUTPUT` は絶対パスの新規 `target/golden/run.*/` にする。

```sh
WGPU_BACKEND=vulkan KRONELLO_GOLDEN=1 KRONELLO_GOLDEN_UPDATE=1 \
 KRONELLO_GOLDEN_OUTPUT="$PWD/target/golden/run.qa004.candidate" \
 cargo test -p kronello-gpu --test golden --locked -- --ignored --nocapture
```

40 シーン・40 frames、全画素 CPU oracle 合格と環境・画像を確認し、clean revision の候補を明示採用する。Windows は profile を `windows-dx12` にする。

```sh
python scripts/golden_adopt.py target/golden/run.qa004.candidate/candidate --profile linux-vulkan
WGPU_BACKEND=vulkan KRONELLO_GOLDEN=1 \
 KRONELLO_GOLDEN_OUTPUT="$PWD/target/golden/run.qa004.compare" \
 cargo test -p kronello-gpu --test golden --locked -- --ignored --nocapture
```

CI の `qa004-platform-golden` は両環境で候補生成と採用済み基準の比較を実行し、常に artifacts を保存する。候補の生成成功は基準比較の成功ではない。採用は自動化しない。Linux hosted runner は Mesa lavapipe を選ぶ。Windows は Direct3D12 の実際に選択された adapter を記録する。`device_type=Cpu` と `software_adapter=true` の結果は software adapter の証拠であり hardware GPU の証拠ではない。基準と比較の device class が変われば拒否する。adapter 不在は非ゼロ終了し、CPU reference に置換しない。

## M1 / M4 校正の実測

2026-10-06、基点 `572a4e80ea98a277d28eb86fc13a865cfb8a76cb` に QA-004 harness の未コミット変更を加えた状態で実行した。比較時の dirty 状態と入力・renderer / shader / oracle / lockfile の hash は provenance に記録される。基準の更新・許容誤差の拡大はしていない。

| 項目 | 既存基準 | 実測 |
|---|---|---|
| adapter | Apple M1 Metal | Apple M4 Metal |
| 機種 | MacBookPro17,1 | Mac16,10 |
| メモリ | 16 GiB | 32 GiB |
| device class | IntegratedGpu | IntegratedGpu |
| 実測 OS | 基準 environment.json | macOS 27.0.1 / 26A434 |

40 シーン、40 frames、20,950 pixels が **全件 pass**。mismatched pixels=0、最大 RGB 絶対差 `0.00048828125`（`coverage-fill-stroke`）、最大 alpha 差=0。許容誤差 `2^-10 = 0.0009765625` のまま、全画素・全成分の絶対 / 相対比較を満たした。実行 9.10 s。M1 と M4 について共通基準の妥当性を確認した範囲であり、将来の全 GPU 世代を保証するものではない。

再現コマンド:

```sh
WGPU_BACKEND=metal KRONELLO_GOLDEN=1 \
 KRONELLO_GOLDEN_OUTPUT="$PWD/target/golden/run.qa004.m4-calibration" \
 cargo test -p kronello-gpu --test golden --locked -- --ignored --nocapture
```

証拠は `target/golden/run.qa004.m4-calibration/` の `report.json` / `environment.json` / `environment-diff.json` / `provenance.json` / actual と差分。ログは `/private/tmp/qa004-m4.log`。CPU adoption gate の 11 tests と Rust golden の通常 3 tests が合格した。Linux / Windows の実測・明示採用・通常比較は未確認であり、QA-004 の正式受け入れはその証拠が揃うまで pending とする。

## Linux Vulkan 基準の採用

[CI 37400761264](https://github.com/soramikan/kronello/actions/runs/37400761264) の
`qa004-linux-vulkan` artifact は 40 scenes / 40 frames の CPU oracle 比較を完了した。
actual adapter は `llvmpipe (LLVM 20.1.2, 256 bits)`、Vulkan、device_type=Cpu、
Mesa 25.2.8-0ubuntu0.24.04.4。hardware GPU の保証には代用しない。

root agent が全 40 PNG の一覧を直接確認し、欠落や異常な描画がないことを確認した。
PR の検証用 merge commit `788331098367f6b431ec778b7bdf301ea268f0c3` の clean な隔離 checkout で
`golden_adopt.py --profile linux-vulkan` を実行し、hash・版・CPU oracle・40 scenes を検証して採用した。
採用ファイルを作業 branch へ複製後も全 artifact の byte size / SHA-256 一致を確認した。
候補 410,593 bytes、fixtures と基準全体 871,856 bytes、最大単一ファイル 176,618 bytes。
生の採用ログは `target/m4-acceptance/linux-golden-adoption.json`、目視一覧は
`target/m4-acceptance/linux-golden-contact.png`。通常比較は [CI 37401385847](https://github.com/soramikan/kronello/actions/runs/37401385847) で成功した。

同じ CI の Windows は manifest を既定 code page で読んだため fixture fetch が失敗した。
正本 text の UTF-8 を明示し、CI も Python UTF-8 mode とした。Windows 基準の採用結果は次節に記録する。


## Windows DX12 基準の採用

[CI 37401385847](https://github.com/soramikan/kronello/actions/runs/37401385847) で
40 scenes / 40 frames の CPU oracle 比較が成功した。actual adapter は Microsoft Basic Render Driver、
Dx12、device_type=Cpu、driver 10.0.26100.33438。software adapter の基準として保持する。

root agent が全 40 PNG を直接確認した後、候補と同じ clean な検証用 merge commit
`91b7b263331ed3a8a13fc8f33184790de687bf85` の隔離 checkout で
`golden_adopt.py --profile windows-dx12` を実行した。全 84 artifact の hash / byte size を
作業 branch への複製後も照合した。候補 401,786 bytes、fixtures と全基準 1,273,642 bytes、
最大単一ファイル 176,806 bytes。許容誤差と provenance gate は変更していない。
採用ログは `target/m4-acceptance/windows-golden-adoption.json`、画像一覧は
`target/m4-acceptance/windows-golden-contact.png`。採用済み基準による通常比較は次の CI で確認する。
