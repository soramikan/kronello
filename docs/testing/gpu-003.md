# GPU-003: macOS hardware decode と resident media/render

正本の受け入れ条件は `docs/backlog/backlog.json`。設計契約は [ADR-0081](../adr/0081-guaranteed-metal-hardware-video-decode.md)。software decode 成功や hardware encode 成功だけを受け入れ根拠にしない。

## 保証対象

| 経路 | 入力 | 出力 / 合成 | unsupported |
|---|---|---|---|
| `gpu_resident_bgra8` | local AVFoundation container、H.264 / HEVC、SDR BT.709 limited-range `yuv420p` | VT strict hardware → IOSurface BGRA8 → same-device Metal import → GPU color/sample → working RGBA16F scene | hardware query false、foreign context、metadata mismatch、HDR/10bit/full-range、unsupported native container |
| `gpu_resident_nv12` | 同上 | VT strict hardware → IOSurface NV12 video-range R8/RG8 → GPU YCbCr→RGB/inverse transfer/sample → working RGBA16F scene | 同上、plane / actual pixel format mismatch |

native compressed demux の resource bound は 262,144 samples / 128 MiB。指定 source time は video track `[start,end)` で検証し、有理数 PTS の最大 `<=time` を選ぶ。VFR / B-frame / reverse / repeated requests を callback order に依存させない。Windows/Linux は未保証で typed unsupported、software backend は明示選択で利用できる。

## 再現コマンド

LGPL FFmpeg と generated media fixture を準備した host で:

```sh
cargo test -p kronello-framebridge --test resident --locked -- --ignored --nocapture
cargo test -p kronello-service --test gpu_resident --locked -- --ignored --nocapture
```

第一コマンドは **2 tests**。generated compressed H.264 を `RequireHardwareAcceleratedVideoDecoder=true` で decode、query true、IOSurface-backed BGRA / NV12 を同じ Metal device へ import する。decoder session と caller buffer の解放後に GPU conversion / group opacity / final render を完了する。灰色四象限の BT.709 inverse-transfer の数値 oracle、alpha / finite、foreign context / dimension / working-space rejection、CPU oracle の resident input rejection を確認する。

第二コマンドは **4 tests**。既存 LGPL-generated CFR / VFR / B-frame NUT から hardware H.264 / HEVC (`hvc1`) MOV fixture を生成し、共有 `Service::RenderFrame` で両形式を実行する。原 testsrc2 画像を保持し、hardware NV12 と software YUV420 の raw Y / UV を全 sample 比較（最大差 <=2）、実 native BGRA / NV12 buffer を検証専用に CPU copy して別実装の inverse-transfer / primaries oracle と全画素比較（最大差 <0.002）する。native oracle の検証用 CPU read/copy は production counter に混ぜず、16,384 B (BGRA) / 6,144 B (NV12) を別記する。

software libswscale RGBA の全画素差と最大差の座標 / 両画素値も残す。native BGRA の chroma conversion と software bilinear chroma upsample、NV12 nearest chroma / unclipped float の差を同一画素規約と誤認しない。時刻ごとに luma / chroma を変える uniform fixture は software RGB とも最大差 <0.045 を要求する。全 fixture で native / software decoder の選択 PTS を有理数の cross multiplication によって完全一致させる。metadata の hardware path / actual transfers、locked stream の半開 end / start 外と native track 外の拒否も確認する。fixture 生成の encoder 成功だけでは合格にならない。

## 実機記録

- root agent による実機実行: Apple M4 / Mac mini `Mac16,10` / 32 GB / macOS 27.0.1 `26A434` / Metal `Apple M4`。
- 基点: `8375caf`、GPU-003 実装中の dirty working tree。最終 clean revision の記録は全変更確定後に追加する。
- 最終 native ownership / gray RGB oracle: **2 passed / 0 failed / 0 skipped**、1.08 s。実行 agent と root agent が同じ host で再確認。
- production H.264 pattern / HEVC hvc1 pattern / time-varying color の **3 passed / 0 failed / 0 skipped**、5.55 s。canonical interval API 整理後の再実行は **3 passed / 0 failed / 0 skipped**、6.53 s。log は `target/evidence/gpu-003/service-formats.log`、native 再実行は **2 passed / 0 failed / 0 skipped**、1.28 s。log は `target/evidence/gpu-003/native-ownership.log`。環境は上記と同じ。
- 代表原 testsrc2: decoded raw Y / UV の hardware/software 最大差 **0**。GPU 対 native oracle の最大線形差は BGRA **0.00048691** / NV12 **0.00097573**。
- software RGBA との差も隠さない: BGRA 最大 **0.6154069** at (55,4)、GPU `[0.21130371,0.21472168,0.9453125,1]` / swscale `[0.8267106,0.104090884,1,1]` / native oracle `[0.21133997,0.21472758,0.9453388,1]`。NV12 最大 **0.42285156** at (50,4)、GPU `[1.4228516,-0.005958557,1.1347656,1]` / swscale `[1,0,1,1]`。chroma filter と整数 RGBA clipping が異なる経路で、native all-pixel oracle と raw decode equality によって sampling / codec 誤りと区別した。
- PTS の実バグを検出して修正: B-frame MOV の AVFoundation edit output 起点 **41/1000** と locked FFmpeg 起点 **1/24** の差 **-2/3000** を、全 compressed sample の output PTS から first PTS を引き、正本 origin を加える exact rational 演算で補正。float や一様 fps への snap は使わない。修正前の PTS は `target/evidence/gpu-003/exact-pts-diagnostic-before-fix.log` に保管。
- production 64×64 一 frame の actual counter: pixel upload **0 B**、control upload **4632 B / 36 operations**、GPU copy **32768 B / 1 operation**、最終 image+status readback **65544 B / 4 operations**。
- 各形式 conversion: pixel upload **0 B** / image readback **0 B** / GPU copy **0 B** / control upload **48 B**。
- 各形式 native scene test の最終出力: control upload **1252 B** / GPU copy **32768 B** / image+status readback **32772 B**。GPU copy と最終 readback を隠さない。
- sandbox 内の Metal execution は adapter 不可で失敗する。これを actual host の decoder failure / 不合格結果と混同しない。

CLI/MCP の flag と JSON wire selection は共有 service へ接続済み。最終 clean revision での全 workspace / 実プロセス結果は root の checkpoint に記録する。Windows/Linux の resident guarantee、HEVC `hev1` MOV、HDR/10-bit は今回昇格せず typed unsupported。

## 公開選択と統計

CLI / MCP: `--backend gpu-resident-bgra8` または `--backend gpu-resident-nv12`。`render.frame` の JSON `backend` は `gpu_resident_bgra8` / `gpu_resident_nv12`。既存 `gpu` / `cpu_reference` は software decode の明示経路。

`FrameMetadata.input_path` に hardware decode / imported format / GPU color sampling / final readback を記録し、`transfer_stats` は backend instance 内の累積 actual execution counters。独立の `render.frame` 要求では instance を作り直す。連番 / tile は同じ instance で増加する。`render.explain` は device 初期化・codec 実行をせず、resident path と upload estimate / policy notices を返す。

最終 CPU output の readback は要求された出力境界。CPU temporal accumulation は resident 強制と併用不可。`UNSUPPORTED_FEATURE` から software backend を明示選択できるが、自動 fallback はしない。

2026-10-06 の実圧縮記述検証追加後は **4 passed / 0 failed / 0 skipped**、5.71 s。`service-formats.log` を更新した。第四テストは、実素材が PQ 10-bit・SDR 10-bit・full-range 8-bit の HEVC であるのに locked metadata を SDR BT709 limited 8-bit と偽装したケースを両 resident 形式で `UNSUPPORTED_FEATURE` にする。入力ピクセルをデコードする前に CMFormatDescription の色タグ、MOV sample entry の `colr`、`avcC` / `hvcC` の chroma / bit-depth を検証する。不明な primaries / transfer は推測せず拒否する。通常 fixture の hardware encoder は出力 `-color_*` だけでは `nclc(2,2,1)` を生成したため、encoder 入力 frame に `setparams` を適用して実タグ `(1,1,1)` を固定した。

追加の実 sRGB 8-bit HEVC を BT709 lock と偽装したケースも両形式で拒否した。CoreMedia が sRGB transfer を返す場合の許可は、原 MOV `colr` が BT709 を明示する場合に限定する。原 `colr` が sRGB の素材を BT709 として処理しない。追加後の全 production suite は **4 passed / 0 failed / 0 skipped**、7.35 s（同じ M4、`service-formats.log` 更新）。
