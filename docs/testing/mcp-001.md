## 再現コマンド

cwd は指定 worktree root。最初の unlocked Clippy で新 crate の Cargo.lock エントリーを追加し、以降は locked を使う。外部 SDK / 非同期 runtime の追加はない。

```sh
cargo clippy -p kronello-mcp --all-targets -- -D warnings
cargo fmt --all --check
cargo clippy -p kronello-mcp --all-targets --locked -- -D warnings
cargo test -p kronello-mcp --locked
python3 scripts/backlog.py render
python3 scripts/backlog.py check
git diff --check
```

## 実装上の決定

- 対応版を structuredContent / outputSchema を持つ上記2版に限定し、両版で text JSON も返す。未対応版は明示エラーにする。この拒否方針は MCP-001 の委任条件によるもので、MCP の版交渉規定が要求する別の対応版を返す動作とは異なる。architecture にこの差異と仕様のリンクを記録した。
- 成功は registry の successful value、エラーは公開 Response の error branch をそのまま使い、outputSchema は両者の union。未知 tool / method は protocol error、既知 tool の引数 / 実行失敗は安定 service code を持つ tool result。
- 公開 API と payload を一致させるため capabilities.get は project を追加しない。これは対象作品のない discovery であり、作品操作の project / render input.project は省略不可。
- schema は共有型から毎回生成し、必要な `$defs` を同梱する。新 registry entry の一覧・schema・dispatch は自動公開される。成功 fixture はこの基点の17操作を扱い、後続操作の成功条件はその担当タスクで検証する。
- registry の read_only は作品に対する値。render.sequence の filesystem 出力があるため、MCP readOnlyHint へ誤って対応づけず `_meta.kronello.readOnlyProject` として返す。
- backend は共有 Service を使用。dev dependency だけで既存 `test-adapter-unavailable` feature を有効にする。通常 build には注入を追加せず、release の debug_assertions がない場合も既存 service の規約に従う。
- 素材文字列を評価せず、arguments を RawValue のまま service の厳格 decoder に渡す。重複 field と浮動小数点値を Value の round trip で変更しない。
