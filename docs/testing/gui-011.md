検証日: 2026-10-08。worktree `kronello-m9-lane-e`、branch `m9-lane-e`、開始 HEAD `8717ae2`。macOS / arm64、Rust 1.95.0・Swift 6.4（Xcode toolchain）の sandbox CPU 実行記録。契約は [ADR-0128](../adr/0128-dual-monitor-and-three-point-editing.md)。

## 実装範囲

### 二画面モニタ

- `EditPage` の viewer 領域を `HStack { SourceViewer; SequenceViewer }` に変更し、Edit ページにソースモニタとプログラムモニタを並置した（`apps/macos/Sources/Kronello/EditPage.swift:20`・`SourceViewer` 104 行〜・`SequenceViewer` 221 行〜）。
- `SourcePreview`（`KronelloCore/Session.swift`）は `.composition(id)` / `.asset(id, stream)` / `.multicam(group, angle)` の安定 ID ベースの wire identity を持ち、表示名や配列位置から導出しない。`PlaybackTarget.source(SourcePreview)` は共有 schema の `RenderTarget::Source` 形にマップする。
- プレビュー surface は 1 セッション内のスロットで多重化する（`kronello-ffi`）。program = slot 0、source = slot 1、export = slot 2 で、`MetalPreview` は target に応じてスロットを選択し、`ExportMetalPreview` は専用スロットを使うため編集画面のモニタを奪わない。`SourceViewer` は `MetalPreview(model:model, source: monitor.source)` でソースを描画する。
- ソースの選択元はプロジェクトパネルの資産行（openAssetInSource）とタイムラインクリップ（openClipInSource → `clip.sourcePreview`）、およびソースモニタ内のソースポップアップ（`sourceChoices()`）。

### ソース側の編集操作

- `SourceMonitor`（`KronelloAppModel/SourceMonitor.swift`）はソースローカルの有理数時刻・In/Out 点・宛先 track オーバーライドを保持する。In/Out・クリア・フレームステップはボタンと `WorkflowSettings` のショートカット（`sourceIn` / `sourceOut` など）の両方で操作でき、表示タイムコードはソースローカル時刻。
- 宛先 track は sequence targets の自動解決が既定で、ポップアップから明示 track を選べる（`sourceDestinationTracks()` / `setSourceDestination(_:)`）。
- `insertSource()` は `edit.insert`（`linked: true` 付き）、`overwriteSource()` は `edit.overwrite`（`split_tail` 付き）を共有 API に発行する。要求は `source`（wire identity）・`source_range [start,end)`・`at`・任意の `track` を含み、`EditOverwriteRequest` の strict schema に合わせて `linked` は insert のみに付ける。
- multicam ソースでは角度ポップアップが `previewSourceAngle(_:)` でプレビュー角度を切り替える（SourceRef は不変で preview target のみ変更）。

## 受け入れ証拠

追加したモデル層テストはすべて実 worker（`apps/macos/Libraries/kronello` を包む `RecordingTransport`、strict `additionalProperties` schema で各 request を実サービスが受理）経由:

| テスト | 内容 |
|---|---|
| `testSourcePreviewWire` | `SourcePreview` 3 ケースの wire 形と preview surface スロット対応 |
| `testSourceOpenMarkingAndWindow` | 資産・クリップ・composition のソース open、ソースローカル窓と `sourceTime(at:)` 換算、In/Out マーキングとクリア |
| `testInsertOverwriteThreePoint` | In/Out + 宛先から `edit.insert` / `edit.overwrite` が発行され、insert は後続を押し退け、overwrite は範囲を置き換える（`split_tail` 分割含む）。宛先 track の自動解決と明示選択 |
| `testMulticamCreatePreviewAndSwitch` | `multicam.create` で group が document に永続化、`.multicam` ソース preview、`clip.angle_switch` が対象クリップのみ付け替え、非 multicam クリップへの適用は拒否 |

Rust 側: `nle7.rs` の `edit_insert_ripples_later_clips_and_uses_targets` / `edit_insert_resolves_audio_targets_and_rejects_mismatch` / `edit_insert_rejects_unresolved_destination_and_source` / `edit_overwrite_replaces_covered_content` が共有サービスの insert / overwrite 意味（targets 解決・straddle 拒否・split_tail）を検証する。

## 制約・既知の限界

- ネイティブ画面での実機確認（二画面の見た目・ショートカット体感）はこの環境では未実行。各操作の接続は実 worker 経由のモデルテストで検証済みであり、画面確認は親エージェントの Computer Use 検証を待つ残件とする（gui-008 / gui-009 の `integration-003.md` と同じ段取り）。
