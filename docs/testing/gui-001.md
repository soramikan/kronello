# GUI-001 の検証

対象は未コミットの `m3-gui1` worktree（開始 revision `a6c73d1d4134c9fe1fb50a8b856564f894ca31f1`）の実装。
本書の成功は CPU / sandbox の検査であり、SwiftPM・署名済み bundle・Metal・画面の受け入れを意味しない。
設計は [ADR-0061](../adr/0061-macos-editor-session-and-ui-state.md)、画面の正本は変更していない [screens](../design-system/screens/README.md)。

## 受け入れ条件と証拠

Swift tests は `apps/macos/Tests/KronelloAppModelTests`。XCTest wrapper と同じ throwing checks を direct compiler runner で実行した。
XCTest source 自体も SDK の XCTest framework / Swift overlay を指定して typecheck する。

| 条件 | 実行した検査 | 状態 / host gate |
|---|---|---|
| 1. 共有 Command / Event | `testGUIEditCLIEventAndNotification`：GUI model → FFI plan/apply（Shape と default Rotation insertion）→ 同じ receipt を CLI replay。Event / revision が完全一致。Rust `node_property_insert_validates_identity_key_and_supports_receipt_undo` は共通 JSON decoder、duplicate ID / key、receipt / Undo / Redo を確認 | direct check 成功。SwiftPM runner と実操作は pending host run |
| 2. UI state 分離 | `testStateIsolationAndRationalTime`：project の bytes を固定して UI state の保存 / 復元後に一致。`testCanvasDefaultsAndLock`：候補表示は edit 0回、解放時だけ1 apply、lock は canvas の選択 / 変形を拒否 | direct check 成功。window で pan / zoom / panel state と revision 不変を確認する |
| 3. 外部 revision reload | `testSelectionReloadAndDeletion` と実 FFI notification を使う `testGUIEditCLIEventAndNotification`：CLI rename rev 3 へ自動追従、stable selection 保持、CLI delete rev 4 で解除・notice。後続の無関係な Event に削除の操作者を誤帰属しないことと数値 Event revision の読取りも検査。FFI `subscription_detects_external_revision_and_job_snapshot` | direct / Rust check 成功。host で pixels と一覧の同期も確認する |
| 4. 自セッション Undo / conflict | `testSessionUndoAndRedo`：過去 Event を stack に入れず、自分の最新 Event を Undo、Undo Event を Undo して Redo。実 CLI rename 後の GUI Undo は `UNDO_CONFLICT`、stack 保持。`testConflictMappingAndExplicitRetry` は structured details と rejected candidate の保持 | direct check 成功。sheet / banner / menu focus は pending host run |
| 5. 個人 state root / project ID | `testStateIsolationAndRationalTime`：`KRONELLO_STATE_ROOT/ui-state/<UUID>.json` と rational num/den を検査。`UIStateStore` は project path を受け取らない | direct check 成功。再起動・既定 macOS root は host procedure で確認 |

補助 `testNumberCommitOnce` は `KRNumberEdit` の連続 scrub / 重複 finish と model を接続し、preview で edit 0回、確定は plan / apply 各1回を確認する。
`testCanvasDefaultsAndLock` は absent Position の初回 authoring を含む。実 FFI check は query の layout / visual bounds の decode も検査する。
`testStateIsolationAndRationalTime` は subframe key の navigation / on-key state と正確な rational time、fractional duration の最後の有効 frame も検査する。

## 実行済みのコマンド

共有 `CARGO_HOME` / `CARGO_TARGET_DIR` / managed `TMPDIR` を維持し、Cargo jobs=3。

```sh
cargo fmt --all --check
CARGO_BUILD_JOBS=3 cargo clippy --workspace --all-targets --locked -- -D warnings
CARGO_BUILD_JOBS=3 cargo test -p kronello-service --test editing --locked
CARGO_BUILD_JOBS=3 cargo test -p kronello-service --lib --test api --locked
CARGO_BUILD_JOBS=3 cargo test -p kronello-eval --test evaluation --locked
CARGO_BUILD_JOBS=3 cargo test -p kronello-model --locked
CARGO_BUILD_JOBS=3 cargo test -p kronello-render --test render cpu_visibility_snapshot_versions_preserve_legacy_and_hide_disabled_subtrees --locked
KRONELLO_STATE_ROOT="$TMPDIR/gui-001-jobs-state" CARGO_BUILD_JOBS=3 cargo test -p kronello-ffi --test boundary --locked
python3 scripts/generate_swift_api.py --check
python3 scripts/build_ffi.py
KRONELLO_STATE_ROOT="$TMPDIR/gui-001-swift-state" python3 scripts/check_gui_swift.py \
  --swiftc /Applications/Xcode-beta.app/Contents/Developer/Toolchains/XcodeDefault.xctoolchain/usr/bin/swiftc \
  --disable-plugin-sandbox --run-checks
python3 -m py_compile scripts/build_macos_app.py scripts/check_gui_swift.py scripts/demo_gui_001.py
git diff --check
```

Rust は editing 18、service unit 7、API 11、evaluation 18、CPU visibility 1、FFI boundary 8 成功。
model crate の integration / doc tests も exit 0。
新しい visibility test は旧 absent visibility=1 の pixels が現在版と同じこと、disabled subtree の透明出力、
旧 version に disabled 意味を混ぜた snapshot の拒否を検査する。metadata が異なるため frame 全体を同一視しない。
Swift は production modules、app / gallery、XCTest source の型検査と共通 **7 checks**。
`--disable-plugin-sandbox` は compiler の内側 sandbox を無効にするだけで、worker の外側 sandbox は維持する。
`--skip-modules` は直前の modules を再利用する補助 option であり、最終検査は新規 build を使う。

初回 FFI boundary は default user state root への書込みで job notification の検査が失敗（7成功・1失敗）。
上記の writable state root を指定した実行では8成功。GPU 成功への読み替えではない。
初回 Swift state 保存は Foundation atomic write が sandbox で失敗した。現在は同ディレクトリの temporary + POSIX rename に変更し、state isolation check を再実行した。
初回 CPU visibility test は pixels ではなく version / hash metadata を含む frame 全体の比較で失敗し、比較対象を pixels に修正した。
削除通知の追加検査では Event の数値 revision の扱いに不具合を検出し、NSNumber の正確な stringValue と削除 Event の照合に修正した。
別の direct compiler 実行は編集中の test source を検知して停止した。コード編集を終了して再検査した最終結果を成功証拠とする。
GUI new project を実 FFI で作成する検査へ拡張した際、通知の reload と apply 後 reload の競合を検出した。
並行 reload の caller は完了を待ち、古い revision 通知を無視するよう修正した。own Event を外部変更と誤表示しない。

SwiftPM は次の実行を試みたが、XCBuild が `.build/out/Intermediates.noindex/XCBuildData/.../manifest.json` に
書けず `NSCocoaErrorDomain Code=513` / `Operation not permitted` で exit 1。ビルド成功とは報告しない。

```sh
swift build --package-path apps/macos --disable-sandbox -j 3 \
  --cache-path "$TMPDIR/swift-gui-cache" --config-path "$TMPDIR/swift-gui-config" \
  --security-path "$TMPDIR/swift-gui-security"
```

## 実装範囲・差分・残件

- 実装: Welcome、共通 toolbar / status、Motion、native preview adapter、overlay transform、Inspector、読取り専用 Dope sheet、
  shared names / visibility / default Property insertion、通知 / conflict / session Undo、ユーザー UI state、開発 bundle script。
- deferred: Curve editor / keyframe 編集 GUI-002、Sequence GUI-003、Template / Export GUI-004、A/V sync AUDIO-002、
  safe-mode session lease、multi-span text / font weight authoring、Bezier control-handle authoring。
- 候補は変換した query AABB overlay と field draft。厳密な候補 pixels / rotated ink outline の再レンダーではない。
  新規 Composition は16:9、既存作品は actual extent ratio を維持する。
  preview pixel size は view geometry / backing scale / zoom から毎回求める。再生・resize と half / quarter resolution の反復で縮み続けないことを host で確認する。
- shared Event に CLI / MCP の種類ラベルと timestamp はない。表示は session UUID / revision と shared details / history。
  UI は種類や時刻を捏造しない。history はページを追って読む。削除 Event が保存履歴に残らない場合は操作者を推測せず履歴への導線と読込 revision を出す。
  safe band の copy は監督の指示で per-request exclusivity を明記した。
- KronelloDesign 追加: `KRWelcome` / `KRRecentProject` / `KRWindowMetrics`、`KRStateBand` / `KRConflictBanner` /
  `KRViewerError` / `KRManipulationOverlay`。既存 segment / tool の個別 unavailable、Inspector glyph の edit disabled、
  `KRLayerRow.diagnostic`。全追加の状態を6 gallery sheets に置く。デザイン仕様文書、backlog、ADR index、open questions は変更しない。
- `cargo test --workspace --locked` / GPU golden / hardware codec / SwiftPM runner / bundle signing / 手動画面検査はこの sandbox の成功証拠に含めない。
