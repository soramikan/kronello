# JOB-001 の検証

対象は `.worktrees/job`、branch `m2-job-001`。開始基点は `0775916`（M0 / M1 と SERVICE-001 / API-001 / TEMPLATE-001 / FX-001 / MEDIA-001 / AUDIO-000 / MCP-001）。2026-10-04、macOS / arm64、Rust 1.95.0 の worker sandbox で検証した。途中で owner の終了により外部中断され、supervisor が `1a273c2` に WIP を保存した。同じ worker の context と同一 worktree で再開し、以下の最終検証を完了した。worker 自身は commit / push を行っていない。

## 実装と実行境界

`kronello-jobs` は作品外の状態 DB / 固定入力 / FIFO lease / heartbeat / cancel / prune / detached spawn を担当する。`kronello-service` が RenderSnapshot の作成と実行を共有し、CLI / MCP は共通 worker 入口を使う。API は `render.submit` / `job.get` / `job.list` / `job.cancel` / `job.prune`、公開 registry は24操作。詳細は [ADR-0050](../adr/0050-fixed-job-execution-and-publication.md)。

画像連番は RGBA16F / PNG / JSON、MOV は同梱 LGPL runtime の ProRes + stereo 48 kHz PCM24。MOV の明示 clips と映像を同じ固定 envelope から出力する。backend はすべて明示 `cpu-reference`。GPU の不在時に暗黙 fallback する実装はない。

全 job test は `tempfile` と `KRONELLO_STATE_ROOT` / `JobConfig::at` を使う。CLI / MCP の実 binary を別プロセスとして起動し、投入元の終了後に状態 DB を別の呼出しから読む。実ユーザー状態 directory は開かない。CLI process test の heartbeat 間隔は50 ms、期限は3000 ms、MCP は50 / 1000 ms。production の既定は1000 / 30000 ms。待機や artifact corruption の注入は `test-job-control` と debug_assertions が両方有効な test build に限る。

## 追加の固定入力・失敗経路

- `fifo_one_slot_and_fixed_snapshot_survive_project_edits`: 投入後に project の fill color を変更しても、両 job の PNG が投入前の同期 CPU render と byte 一致。編集後の同期 render は異なる。job manifest の revision / snapshot hash は投入時点のまま。
- `worker_checks_saved_schema_semantics_features_and_input_hash`: queued 入力の envelope schema、snapshot 意味版、required_features を別々に変更して worker の互換性検証を確認する。互換性ケースは保存 envelope の byte hash もテスト側で更新し、単なる hash 失敗と区別する。byte hash を更新しない破損は JOB_INPUT_HASH_MISMATCH。
- `changed_asset_content_fails_worker_with_typed_error`: 先行 job で slot を占有し、queued job の素材を同じ byte 長で変更。worker が ASSET_HASH_MISMATCH で失敗し、final output を作らない。
- `worker_verifies_saved_font_lock_before_output`: 固定 FontRef に対し違う font bytes を渡し、worker 開始時の ASSET_HASH_MISMATCH を確認する。
- `cancel_running_and_queued_jobs_cleans_temporary_output`: 実 CLI job.cancel を running / queued の双方へ発行。両方が canceled、final output なし、temporary directory が残らない。
- `duplicate_worker_cannot_fail_or_steal_an_active_job`: 同じ ID の worker を再度実起動し、JOB_ALREADY_OWNED で拒否。元 PID と running を維持し、元 worker が成功する。
- `mov_export_uses_fixed_video_and_audio_snapshot`: 明示音声 clip を持つ実 job が ProRes / PCM24 MOV を確定し、映像・音声 report の RenderSnapshot hash、3 frame、2 stream を照合する。別形式の成功を MOV の代替として扱わない。
- `invalid_configuration_ids_and_newer_database_are_rejected`: 0 slot、path traversal 型の ID、未知 DB 内部版を拒否する。

## 失敗・中断の記録と修正

- test dependency 追加直後の `cargo test -p kronello-cli --test jobs --locked` は exit 101、テスト未実行。crate-scoped check で lock を更新した。
- 初回の同コマンドは exit 101、7 passed / 2 failed。MOV の internally tagged enum decode が arbitrary_precision の数値を f32 へ渡せず、共有 wire と同じ RawValue decode に修正した。CLI heartbeat の1秒期限を越える失敗もあった。この初回の worker log は取得できておらず、正確な原因は確定していない。テスト期限を3秒にし、state open ごとの不要な schema 書込みを除去した。最終の SIGKILL test は3秒期限そのものを検証する。
- 次の同コマンドは exit 101、8 passed / 1 failed。音声 fixture より長い placement を指定して AUDIO_SOURCE_TOO_SHORT になった。音声 clip を1 frame の placement に修正した。範囲外は明示 placement 外の silence であり、短い素材を黙って埋める fallback ではない。修正後9 passed、追加検証後11 passed を観測した。
- 初回 `cargo test -p kronello-jobs --test state --locked` は exit 101、3 passed / 1 failed。10 ms の期限が slot 取得前に切れた。expiry の単体テストは DB の heartbeat を backdate する決定的な手順へ変更し、実 SIGKILL 検出と分けた。修正後・所有確認追加後・再開後は各4 passed。
- レビューで、duplicate worker が既存 job を failed にできる問題と、claim の拒否時に heartbeat recovery transaction が rollback する問題を修正した。PID 所有確認と拒否時の commit を追加し、上記の専用 tests で確認した。
- 外部中断時の12-test コマンドは完了結果を観測していないため pass と数えない。再開後の同コマンドは12 passed。
- 初期の補助編集コマンドは、here-document の temporary file 作成拒否、backlog の collection 名の取り違え、shell quoting の parse error により各 exit 1。いずれも書込みを完了しておらず、apply_patch / items による更新へ修正した。fixture の存在確認では directory 不在を観測し、取得後は fixture 利用 test が成功した。設計の旧文言不存在を確認する rg の exit 1 は no matches。
