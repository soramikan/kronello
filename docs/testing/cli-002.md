## テスト専用の境界

service の feature `test-adapter-unavailable` は既定無効。CLI の dev dependency が service feature を有効化するため、debug profile の通常の integration test は追加 option なしで故障を注入できる。CLI の同名 feature は service feature へ転送する。

`KRONELLO_TEST_ADAPTER_UNAVAILABLE=1` は service の GPU factory 内でのみ処理し、`cfg(all(feature = "test-adapter-unavailable", debug_assertions))` で囲む。通常の feature なし build と、標準 release profile の feature あり build は故障注入を含まない。release profile での binary 故障注入テストはコンパイル対象外。環境変数はテスト対象の child process にだけ渡し、通常の child 起動では明示的に削除する。service 単体テストは private factory を差し替えるので環境変数を変更しない。

## 検証コマンド

すべて `.worktrees/store` を作業ディレクトリとし、Cargo の書き込み可能な既存 cache として `CARGO_HOME=/private/tmp/kronello-store-cargo` を使用する。

```bash
python3 scripts/fetch_fixtures.py --offline
cargo test -p kronello-service -p kronello-cli --locked -- --skip gpu_
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo clippy --workspace --all-targets --locked --features kronello-cli/test-adapter-unavailable -- -D warnings
cargo test --workspace --exclude kronello-framebridge --exclude kronello-gpu --locked -- --skip gpu_
cargo check -p kronello-cli --release --locked --features test-adapter-unavailable
cargo build -p kronello-cli --locked
python3 scripts/backlog.py render
python3 scripts/backlog.py check
```

通常 build の binary に故障注入の環境変数名と診断文字列が含まれないことも、次のコマンドで確認した。

```bash
python3 - <<'PY'
from pathlib import Path
binary = Path('target/debug/kronello').read_bytes()
assert b'KRONELLO_TEST_ADAPTER_UNAVAILABLE' not in binary
assert b'test-only injected adapter unavailability' not in binary
PY
```
