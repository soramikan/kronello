## 受け入れ条件と証拠

| 条件 | テスト / 確認内容 | 状態 |
|---|---|---|
| 1: track lock・clip enable/disable・track targeting をモデルと共有 API に追加する | `TrackState.locked`（`#[serde(default)]`）、`Clip.enabled`（既定 true で `true` の直列化を省略）、`Sequence.targets: Option<TargetTracks>` を `kronello-model` に追加。`TimelineCommand` に `clip_enable_set` / `sequence_targets_set` を追加し、いずれも `EditCommand::Timeline` 経由の plan / apply / 選択的 Undo で動く。service `nle5::legacy_documents_default_track_lock_clip_enable_and_targets`: 旧文書（`locked` / `enabled` / `targets` 欠落）の default 読み込み、`enabled = true` は JSON に `enabled` キーを書かない往復、`enabled = false` の保持。`nle5::sequence_targets_set_validates_persists_and_clears`: 未存在 track の `SOURCE_MISSING`、種別不一致の `INVALID_CLIP`、全欠落 payload の `None` 正規化、export 文書への永続化、後続イベントと鍵が重なる undo の `UNDO_CONFLICT` | CPU 検証 |
| 2: ロック済み track 上の clip・track 自身への変更を計画時に `TRACK_LOCKED` で型付き拒否する | `nle5::locked_track_rejects_every_clip_mutation_atomically`: `clip_delete` / `clip_move` / `clip_trim` / `clip_stretch` / `clip_split` / `clip_slip` / `clip_slide` / `clip_roll` / `clip_time_set` / `clip_enable_set` / `clip_set_volume` / `clip_set_effects` / `clip_freeze` / `marker_set`・`marker_move`・`marker_remove`（clip 指定）/ `clip_place` / `clip_insert` / `clip_overwrite` / `ripple` / `ripple_delete` / `transition_set` / `transition_remove` を一つのロック済み track に対し網羅的に拒否。各拒否は plan 失敗で文書・revision を変えない（atomicity を export で比較）。slide / roll は隣接吸収 clip も編集集合に含めて検査。`linked` 指定の partner 側操作と `clip_link` の再リンクは、リンク成分にロック済み clip を含むため `TRACK_LOCKED`。`EditCommand::PropertySourceSet` は `property_mut` の共有解決点で同じく `TRACK_LOCKED`。sequence 直下の `marker_set`（clip なし）/ `work_area_set` / `sequence_targets_set` はロック下でも成功し、`track_state_set` で unlock 後に `clip_delete` が成功することを確認 | CPU 検証 |
| 3: 無効化クリップは区間を占有しつつ映像・音声・字幕・トランジションへ寄与しない | `nle5::clip_enable_set_disables_contribution_keeps_occupancy_and_undoes`: 無効化後の CPU レンダリングは全画素 α=0、occupancy により重複配置は `CLIP_OVERLAP`、content end は無効 clip を含み、undo で復元。`nle5::disabled_clip_keeps_transitions_out_of_rendering`: crossfade 中点で outgoing の寄与が合成に残ること、outgoing 無効化で incoming が不透明に単独描画されること、incoming 無効化で hole になることを CPU 参照バックエンドで確認。`nle5::disabled_caption_clip_exports_no_cues_and_keeps_occupancy`: caption clip の無効化で SRT export から cue が消え、区間とメタデータは残る。`audio4::disabled_clip_mixes_silence_while_keeping_timeline_occupancy`: ミックスが無音になり再実効化で元 PCM に戻る。`kronello-eval` の `evaluate_sequence` は disabled clip を single-active-clip 規則の対象外とする | CPU 検証 |
| 4: GUI のトラック制御操作を接続し Undo を確認する | `ui.locked` はモーションのレイヤーロック専用に整理し、シーケンス track 側の全ガードを `EditorModel::trackLocked`（`sequence.query` の永続 `TrackState` 読み）へ置換。`setTrackLocked` は `track_state_set` で persisted visible / muted を再送出して toggle。`KRTrack` ヘッダに lock / target（crosshair）ボタンと dim 表示を追加し、`lane` / `clipView` / インスペクタの全操作が persisted lock を参照。clip インスペクタに `clip_enable_set` の「有効」チェックボックスと無効 clip の 0.4 不透明度表示を追加。Undo は共有 `edit.undo` のまま（NLE-002 系の選択的 Undo 規則に従う） | host GUI 検証（下記） |

## host GUI 検証（2026-10-09、`m8` 統合ブランチ `1de1a3b` 以降）

`target/m8-acceptance/gui-audit/edit.kronello`（video×2・audio×1 実素材、`KRONELLO_FONT_INPUTS` で fixture フォント供給）を `target/macos/Kronello.app` で開き、open-computer-use で実機操作した。

- V1 track の lock ボタン押下 → `track_state_set` が適用され revision が前進し「保存済み」まで遷移。lock ボタンが selected 表示になり、V1 の表示切替ボタンが disabled・ヘルプ「ロック中または実行中は切り替えられません」に変化
- ロック中の V1 clip はクリックしても選択されない（`clipView` の `.disabled(locked)` ゲート）。undo ボタンが有効化
- A1 track の target ボタン押下 → `sequence_targets_set` が適用・永続化され selected 表示
- V2 の composition clip を選択し「有効」チェックボックス OFF → `clip_enable_set` が適用・rev 前進。プレビューから clip の映像寄与（テキスト・矩形）が消え下位 V1 単独表示になり、レーン上の clip が 0.4 不透明度表示に変化
- 全操作が共有 Command/Query API 経由で永続ドキュメントに記録されることを確認（GUI 専用状態なし）

## Public API / schema

- `TrackState.locked`、`Clip.enabled`、`Sequence.targets` / `TargetTracks` を `kronello-model` に追加。いずれも serde default により旧文書をそのまま開ける。
- `TimelineCommand` に `clip_enable_set` / `sequence_targets_set` / `clip_freeze` を追加（`clip_freeze` は NLE-006 側の記録も参照）。エラーコード `TRACK_LOCKED` を追加。
- `sequence.query` の応答は `Sequence.targets`・`Track.state.locked`・`Clip.enabled` を含む。`captions.export` は disabled cue を出力しない。
- `schemas/project-v1.schema.json` / `schemas/api-v1.schema.json` / `GeneratedAPI.swift` を再生成。schema 番号は 1 を維持。
