### 8bit 量子化の再現手順

次の数学的参照は 1,024 点の sRGB ramp が 8bit では 256 段階になり、
隣接する同値 pair が 768 個あることを確認する（exit 0）。
GPU 表示器の見え方や dither の視覚効果を測定した結果ではない。

```sh
python3 -c 'ramp = [round(i * 255 / 1023) for i in range(1024)]; levels = len(set(ramp)); adjacent = sum(a == b for a, b in zip(ramp, ramp[1:])); assert (levels, adjacent) == (256, 768); print(f"8-bit ramp: {levels} levels, {adjacent} unchanged adjacent pairs")'
```

## API / schema / cache

`Gradient` の各 variant に省略可能な `options`、新 variant `focal_radial` / `conic`、
`TextStyleSpan.gradient` を追加。JSON の project / API schema version は 1 の additive extension。
`GradientOptions.interpolation_version=1` と snapshot / metadata の
`gradient_interpolation=vec004-explicit-interpolation-v1` を保存する。
既存 Color Property の補間版・layout / vector / coverage / stroke / color の版は変更しない。
旧 Project の省略 options は VEC-003 値に正規化し、旧固定 RenderSnapshot の意味版は拒否する。

`ShapeError::InvalidGradient` / `InvalidParameter` / `MissingProperty`、
`TextError::Gradient`、`GpuError::InvalidInput` を維持・利用する。
`ShapeError::UnsupportedGradientVersion` / GPU の未知版は最終レンダーで `UNSUPPORTED_FEATURE`。
不正 geometry / 特異写像等は最終レンダーの `RENDER_ERROR`。新しい wire error code は追加しない。
未知 JSON 欄は opaque として往復し、必要な最終出力は `UNSUPPORTED_FEATURE`。

layout / geometry key は paint を除外。warm layout は各 style の最新 gradient を glyph に付け直す。
raster key の既存 resolved paint 直列化に全 options が含まれ、意味版と逆写像も区別する。
fill / stroke の gradient payload を Box にして enum を肥大化させない。
text inspector は gradient stops を見て透明 / 黒の paint を判定する。

## supervisor のホスト検証（2026-10-05、Apple Silicon + Metal）

FX-002 を含む統合ブランチを取り込んだ後（merge `3323c63`）に `cargo test --workspace --locked` を実行したところ、
`gpu_vec004_gradients_match_cpu_in_both_working_spaces` と `gpu_all_scene_pixels_match_cpu_reference` が
`gradient-repeat` の 4 画素（1024 中、RGB 誤差最大 0.033、alpha 誤差最大 0.037）で失敗した。

原因の切り分け: fill gradient を外しても失敗し、stroke gradient を外すと成功した。stroke の写像では 4×4 sample と
paint transform の係数により parameter が 1/1600 px の格子に乗る。gradient 端点 `(0,0)`〜`(12,0)` だと t = 2.45 の hard stop
（alpha 0 → 0.6）にちょうど一致する sample があった。CPU は f32 で 2.4499998 となり手前の stop を選ぶ。Metal は FMA 融合によって
2.45 以上となり、次の stop を選ぶ。reflect も同じ画素で一致しなかった。実装の不具合ではなく、fixture が不連続点の同値を含んでいたことが原因である。

対応: linear の 6 シーン（text を除く）の端点を `(0.0003,0)`〜`(12.0003,0)` に変えた。全 sample の parameter が
hard stop・周期境界から 0.0003 px（f32 の誤差の 1000 倍以上）離れることを全 32×32×16 sample で確認した。許容誤差は変えていない。
ADR-0066 に不連続点での CPU / GPU 一致の扱いを追記した。修正後に `cargo test -p kronello-gpu --locked` は全テストが成功した。
