# GUI-009 macOS 字幕編集 UI — 受け入れ記録

状態: `m7-lane-d2` の作業ツリーで実装と自動検証を完了し、モデル / コマンド層の条件は確認済み。ネイティブ GUI の実機確認は 2026-10-07 に `integration-003.md` の GUI 経路検証として実施済み。[ADR-0107](../adr/0107-caption-track-and-cue-model.md) に基づく。

## 実装した範囲

- caption lane: `orderedTracks` を caption → video → audio の順に変更し、キューが全 video レーンの上に並ぶ既存のレンダリング順序と一致させた。レーンヘッダは `C1`… の番号、`KRMediaKind.subtitle`（`.captions` アイコンと字幕色）、映像系の visible トグルを使い、audio 系の mute 操作とは分離した。`track_state_set` は既存のまま流用する。
- クリップ認識: `EditClip.kind` はクエリ kind `caption` を `.subtitle` へ写像する。`clipName` は `source_ref.caption` が指す `CaptionDocument` の先頭行を表示し、未解決時は「字幕」を表示する。選択・移動・トリム・削除は既存の汎用ジェスチャをそのまま通る。分割（ブレード）はキューに source window が存在しないため対象外とし、ブレードツール中も通常の選択・移動・トリムのみを受け付ける。caption track への素材ドロップは `beginAssetGesture` で拒否する。
- 字幕編集パネル: `CaptionInspector`（新規 `CaptionInspector.swift`）を Clip Inspector の「字幕」セクションに追加。本文（複数行）、書体（family + weight、登録済み locked font のみ）、サイズ、文字色、縁取りの有無・幅・色、背景の有無・色、9 方向アンカー、オフセット（%）、セーフエリア（0–50%）を編集できる。すべてのコミットは `caption_set` 1 コマンドとして共有の `submit` / `apply` 経路を通り、Undo・revision 競合・プレビュー再描画は共通パイプラインに従う。`version` / `id` / `spans` / `format` など未編集フィールドは辞書ごと保持する。
- 本文編集の span 保存: `captionSpans` は、新テキスト内で grapheme 境界が揃い、かつ同一バイト列が同位置に残る span のみを残す。編集で範囲がずれた・内容が変わった span は検証に落ちる前に取り除く。
- 追加経路: トラックツールバーの「字幕を追加」が `addCaption` を呼び、caption track が無ければ `track_append` も含めて `track_append` + `caption_set` + `clip_place` を 1 Event として適用する（`captionAddCommands`）。クリップは `source_in=0`・恒等 linear time map・`audio_retime=reject` の字幕固有の契約を満たす。配置はプレイヘッドに 2 秒。適用成功後に新クリップを選択する。
- フォント: locked font が 1 つも無い状態での追加は `FONT_MISSING` の型付きエラーとして表示し、架空の FontRef は生成しない。プレビュー用の `fontInputs` を拡張し、caption の base / span フォントと `kronello.caption.font` クリップオーバーライドを描画入力へ含めた。
- 字幕クリップでは「ソース開始」「時間」（速度・逆再生）の行を表示しない。いずれも共有モデルが字幕に許可しない操作である。

## モデル / コマンド層で確認済みのこと

- `caption_set` は検証済み `CaptionDocument` の upsert で、変更は該当キューと依存クリップの invalidation により revision 再読込・再描画に伝播する（サービス側の既存実装）。
- 字幕クリップの `clip_move` / `clip_trim`（subset のみ）/ `clip_delete` は共有 timeline コマンドが受理する。分割はモデルが恒等 time map を要求するため GUI からは発行しない。
- Undo は各操作 Event を巻き戻し、追加経路の 3 コマンドは 1 Undo で消える（選択的 Undo の保守的競合により、同一キーに触れる後続 active event が残る場合は `UNDO_CONFLICT` になる既存仕様）。

## 制約・既知の限界

- 書体選択は `font.pin` 済みの locked font に限る。登録 0 件では追加も編集もできず `FONT_MISSING` を表示する。
- `caption_set` はキュー全体の upsert なので、複数 cue が同じドキュメントを共有することは無い。
- ネイティブ GUI の実機確認は `docs/testing/integration-003.md` の「GUI 経路の検証結果」で実施済み（2026-10-07）: C1 caption lane のクリップ表示、cue のレンダリング（編集後本文・スタイル span 含む）、caption クリップ選択時の Inspector 字幕セクション（本文・書体・ウェイト・サイズ・文字色・縁取り・縁幅・縁色・背景・配置）を実画面で確認した。ドラッグ・Undo の目視はモデル層テストで担保し残件としない。
- `EditPage.swift` は D1 レーンと並行変更の可能性が高い。`orderedTracks` / `trackNumber` を `KronelloAppModel` 側へ移動済みで、`EditPage` の差分は lane ヘッダ・ブレード抑止・Inspector セクション挿入・追加ボタンのみに限定した。
