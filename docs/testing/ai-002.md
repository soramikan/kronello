# AI-002 検証

状態: `done`。`kronello-m9-lane-d` の作業ツリーで受け入れた。main への統合・各 OS CI の保証とは区別する。[ADR-0125](../adr/0125-scene-detection-boundaries.md) に基づく。正本の条件は[バックログ](../backlog/backlog.json)の「映像のシーン境界を自動検出する job を実装する」「検出結果をマーカー/クリップ分割へ適用できる」である。

## 受け入れ対応

- 自動検出 job: `scene.detect`（`crates/kronello-service/src/scene.rs`）は不変の fixed-input job として locked source asset・stream index・解析 range・検出パラメータを固定し、`<project-stem>.scene/<scene-asset-id>.json` を managed destination として atomic に publish する。worker は `kronello-media` の `next_rgba` で frame を順次 decode し、復帰時は receipt と project 登録を再検証する。
- 決定的検出器: 新規 crate `kronello-scene`（`src/detect.rs`）は輝度ヒストグラム差分と edge-change score を重み付き合成し、適応閾値（平均 + σ・peak ratio・最小間隔）で境界を出す。乱数・外部プロセス・ML モデルは使わず、`SCENE_DETECT_MAX_FRAMES` / `SCENE_DETECT_MAX_PIXELS` を超える入力と不正な frame 列は型付き拒否する。境界は新シーン先頭 frame の正規化有理数時刻と `[0,1]` の confidence を持つ。
- 結果の永続化: 結果は versioned `SceneBoundaryAsset`（`crates/kronello-model/src/scene.rs`）として document に保存される。`SceneSource` は source asset id・stream index・元コンテントハッシュをロックし、`validate` は version・range・frame 数・境界の単調性と confidence・payload ハッシュを検査する。source が変わると stale として型付き拒否される。
- マーカー/クリップ分割への適用: `scene.apply` は shared edit planner 経路の 1 mutation で、`markers` モードは決定的な marker id、`split` モードは逐次 split と決定的な right-clip id を生成する。base revision・idempotency key・session・track lock・track/clip scope・最小 confidence を既存 NLE と同じ契約で検査し、undo は一括で戻る。CLI `scene detect|apply`、wire、API registry、MCP は同じ Request/Response 契約を共有する。

## 保証範囲外

- 検出器は輝度ヒストグラム + edge-change の決定論的ヒューリスティックであり、意味的シーン理解（人物・物体認識）は行わない。ML ベース検出の追加は後続タスク。
- `scene.apply` の split は映像クリップの編集のみで、音声クリップの連動分割や ripple は本記録の対象外。
- 検出パラメータの GUI 編集は GUI 側の後続作業。本 lane は共有 API までを保証する。
