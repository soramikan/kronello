# QA-002: GUI / CLI / MCP の等価性と日本語 IME

対象: `m3-qa2`、開始 revision `8523637995defe874e64db1845fa7abd15c17def` に未コミット変更を加えた worktree。
direct Swift / CPU の実行結果と SwiftPM / 実アプリ / macOS 日本語入力の手動受け入れを区別する。
backlog、ADR index、open questions、design-system の仕様は変更しない。共有コアの意味・schema は変更しない。

## 条件と証拠

| 受け入れ条件 | 検査 | 証拠 |
|---|---|---|
| 同じ編集の snapshot が三入口で同一 | `QAEditorTests.testScriptedGUIEquivalence` / `QAChecks.verifyEquivalence`、Rust `scripted_cli_mcp_and_optional_gui_snapshots_match` | 固定 `tests/qa-002/scenarios.json` の document と client ID。GUI は本番 `EditorModel` → `NativeProjectTransport` → 実 FFI session、CLI は実 binary process、MCP は初期化した実 stdio process。独立した三つの `.kronello` に対し各操作後の full `project.export.document`、revision、history Event 件数を照合する |
| 未確定 IME を履歴へ commit しない | `QAEditorTests.testMarkedTextCommitsOnceAndEscapeCancels` / `QAChecks.verifyIME` | 本番 `KRCommittedTextView` の `NSTextInputClient.setMarkedText` / `unmarkText` / `insertText` / Escape と、実 EditorModel / FFI の plan・apply 件数。変換中0回、Escape後0回、確定ごと各1回、続く Return / blur は重複なし。名前・Text・parse可能な数値の入力を含む |

23 シナリオは Position X/Y、Scale X/Y、Rotation、Opacity、日本語 rename / Text（合成済み文字と結合濁点 U+3099、IVS U+E0100）、
disable / enable、navigator の既存 Curve への insert、フレーム単位の move、Hold / Linear / Cubic、
aligned / broken tangent、複数キー削除、最後のキーの Constant 変換、session Undo / Redo。
数値の GUI 操作は `PropertyPresentation` の倍率で表示値を変換し、preview は0要求、commit は1 batch と検査する。
GUI が生成した command は固定シナリオの command とも照合する。CLI / MCP は GUI の Event / receipt を replay しない。
各入口の Undo は自分の成功 Event ID、Redo は自分の Undo Event ID を使用する。service 生成の Event ID / timestamp は同一化しない。
client の document / node / property / curve / text ID は固定して同じものを供給する。
GUI が発行した session ID / idempotency key も記録し、同じ ID を CLI / MCP の独立した適用へ渡す。
Undo の参照先 Event ID は各 store が生成した自分の Event であり、他入口の receipt は渡さない。

canonical JSON は object key をソートし、array 順と文字列の UTF-8 をそのまま保持する。
この fixture の既知の有限数値は f64 として正規化して Foundation の `1` と Serde の `1.0` を同じ数値にする。
未知データの巨大整数・数値の綴りを変える契約ではない。Unicode normalization はしない。
byte-for-byte の比較と各 canonical document の SHA-256 は Rust integration test が作る。

`cargo test -p kronello-cli --test qa_equivalence --locked -- --nocapture` を順に実行する。
`KRONELLO_QA_EVIDENCE_DIR` を設定すると Rust test は GUI の証拠ファイルを必須とし、fixture 一致と三入口を比較する。
設定しない通常 Rust suite では独立した CLI / MCP の比較だけを検証する。この違いを report の `gui_compared` に記録する。
単独で Rust test を実行するときも `cargo build -p kronello-mcp --locked` で実 MCP binary を先に用意する。

JSON は実行時の成果物であり、ソース fixture と違って Git に採用する baseline ではない。

## 入力境界の修正

従来の SwiftUI `TextField` draft は Return / blur でまとめて確定するが、marked text を直接判定していなかった。
共有 `KRCommittedTextInput` を `KRTextField` と NumberField の直接入力だけに使い、
native AppKit の marked text がある間は callback を発行しない。通常の keystroke もローカル draft。
`unmarkText` / composition を置換する `insertText` の確定、Return / blur は一つの callback、Escape は取消。
`insertText` 中の入れ子 `unmarkText` を保護し、続く Return / blur を二重送信しない。
変更判定を Swift の文字列等価（Unicode canonical equivalence）から UTF-8 byte 比較へ変更した。
従来の比較を残した native probe では、合成済み「が」→結合文字「が」の draft が6 bytesへ変わっても callback が0回だった。
修正後はこの変更も一つの Event として保存する。三入口の fixture と実 FFI の native regression に両表現を含める。
NumberField の scrub / 矢印 / shared PropertyPresentation は従来の経路を使う。
規則を architecture 10 に具体化した。既存 ADR の native input / UI draft 方針の実装なので新 ADR は不要。

macOS host で同じ checkout / revision / fixture を用い、次を実行する。

```sh
python3 scripts/build_ffi.py

python3 scripts/demo_gui_002.py --output-root target/qa-002-ime-review
KRONELLO_STATE_ROOT="$PWD/target/qa-002-ime-review/state" \
  KRONELLO_FONT_INPUTS="$PWD/target/qa-002-ime-review/fonts.json" \
  target/macos/Kronello.app/Contents/MacOS/Kronello "$PWD/target/qa-002-ime-review/motion.kronello"
```

新しい output root を使い、macOS Kotoeri / 「日本語入力」ローマ字入力を選ぶ。
Dark / Light の両方で、Inspector の Name、Text、Opacity の直接入力を繰り返す。

1. 始める前の status revision と CLI `history.list` / `project.export` を保存する。
   Name / Text で `nihongo` をゆっくりタイプし、下線付き「にほんご」がある間、作品 revision と Event 件数が変わらない。
   キーごとに status が「保存中」にならず、入力中に型付きエラーを出さない。
2. Space で変換し、候補一覧を開き、矢印 / Space で複数の候補を選ぶ。
   選択中も Event は0増加。Return で候補を確定すると一つの Event に「日本語」が入り、一回の Undo で元へ戻る。
   その直後の Return、Tab、別欄クリックは Event を追加しない。
3. 別の文字列を変換し、Escape で候補を取り消す。IME が一回の Escape で仮名の marked text に戻す場合は
   marked text がなくなるまで取消を続ける。取消後に blur しても Event は増えず、Undo stack も増えない。
4. 通常入力または paste で結合濁点を含む `が` と IVS を含む文字列を入力する。
   Return / blur で一つの Event。export の UTF-8 を入力と照合し、style range の end が UTF-8 byte 数と一致する。
   合成済み「が」を結合文字「が」へ置換しても変更を落とさず、一つの Event として UTF-8 を保存する。
   同じ bytes の確定を繰り返しても Event を増やさない。
5. Name / Text の普通の未変換入力を途中で Escape し、元値へ戻って Event0。
   普通の入力を Return、別欄クリック、Tab でそれぞれ確定し、各一つの Event。
   placeholder、選択範囲、キャレット、水平の長文表示、Tab / Shift-Tab、focus ring、VoiceOver の名前を確認する。
6. Opacity をクリックして直接入力する。日本語入力で数値を変換中も Event0。
   確定後一つの Event、Return / blur は追加0。Escape で数値を取消し、元値と履歴を保持する。
   48.25% の確定値が export では0.4825である。通常の数値入力、scrub、矢印操作も再確認する。
7. 各操作の前後の export / history、OS・入力ソース・テーマ・build revision と screenshot を残す。
   OS の実候補ウインドウ、focus 移動、VoiceOver、実アプリでの長文挙動は direct NSTextInputClient check だけでは受け入れない。
