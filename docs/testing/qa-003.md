# QA-003 の検証

2026-10-03。GPU golden の対象を Apple Silicon ネイティブ + Metal の共通基準へ変更し、M1 開発機で 21 シーンの初回基準を登録した。許容誤差は `compare_pixels` の既定値 `2^-10`、CPU oracle 比較も維持する。性能計測の第一基準機（M4 Mac mini 32GB）は変更しない。

## 受け入れ条件と証拠

| 受け入れ条件 | 実装・確認 |
|---|---|
| ADR-0038 の golden 固定環境だけを新 ADR で置換し、Apple Silicon + Metal を共通比較環境とする | [ADR-0047](../adr/0047-apple-silicon-metal-golden.md) を採用。ADR-0038 は部分置換、ツールチェーン・CI の条項は維持。ADR index と architecture 12 / 13 を更新。`cpu_environment_gate_ignores_provenance` が native target + Metal の許可、Intel / Linux / Vulkan の拒否を確認 |
| M1 開発機で基準を登録し、明示 golden が `2^-10` で合格する | clean revision `96babb20c76c19d2dd12e8fe7d4ad8391ca3ea59` で UPDATE、明示採用、通常比較がすべて exit 0。比較は **21 シーン / 21 frames / 6,870 pixels、全シーン mismatch 0**。基準は `507c3e28dea255ddc44a60fb2188cf7ca85d91ff` に登録 |
| adapter / OS / 機種は provenance として保存し、比較の可否判定に使わない | `environment.json` / `provenance.json` / `adoption.json` に保存。比較 gate の入力は target と backend のみ。環境差分は記録だけ行い、基準との一致を要求しない。Python の `test_model_os_adapter_name_are_metadata_only` で任意の機種・OS・adapter 名でも検証が通ることを確認 |

## 実装と採用の境界

- harness: `crates/kronello-gpu/tests/golden.rs`。M4 機種・メモリ・OS / driver fingerprint の一致判定を削除した。対象 platform / backend は検査し、基準のシーン設定と比較方式の版は厳密一致、全 artifact は採用 manifest の SHA-256 / byte 数で検証する。CPU oracle と baseline の両方に全画素を比較する。
- 基準: `tests/golden/apple-silicon-metal/`。21 RGBA16F、21 表示 PNG、1 外部 straight sRGB RGBA16F、scene manifest / environment / provenance / adoption manifest。`adoption.json` は 46 ファイルの hash と byte 数、シーン設定、許容誤差の版・値、環境・provenance を記録する。カタログと README を含む基準集合は 49 ファイル。
- 明示採用: `python3 scripts/golden_adopt.py <run>/candidate`。current / candidate dirty 状態、revision と HEAD の不一致、対象外 backend / target、未完了・対象ゼロ・シーン不一致、hash / size 不一致、非有限値、不正 alpha、fixture 上限超過を拒否する。全検査後に manifest と byte 集計を出力し、staging から基準集合を置換する。publish 失敗時は既存基準を復元する。
- UPDATE は候補生成だけ。通常比較は採用後の未コミット baseline 差分がある tree でも実行でき、dirty 状態を provenance に保存する。候補の採用は clean HEAD に限る。通常比較時には baseline 生成 revision と現在 HEAD の一致を要求しない。
- `cpu_baseline_integrity_rejects_missing_and_modified_artifacts` は採用 manifest / 画素ファイル欠落、hash 改変、設定変更、対象ゼロを拒否する。Python の 10 regression tests は採用・拒否・publish 失敗時の復元を synthetic fixture で検証する。これらは GPU 画素比較の代用ではない。

## Worker sandbox の検証

開始 HEAD `b69446fa5522a54f6ebefd913f5a4fdcd5a6157c` に QA-003 の未コミット差分を適用した main checkout で実行した。Metal adapter は利用不可であり、GPU / FrameBridge 実行は supervisor の host 結果と区別する。既存の default `CARGO_HOME` を使った。

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --exclude kronello-framebridge --exclude kronello-gpu --locked -- --skip gpu_
cargo test -p kronello-gpu --locked -- --skip gpu_
python3 scripts/test_golden_adopt.py
python3 scripts/fixtures.py check
python3 scripts/fetch_fixtures.py --offline
python3 scripts/backlog.py check
git diff --check
```

- すべて exit 0。workspace は **264 passed**（doc test 2 件を含む）、0 failed、4 GPU tests filtered。
- GPU crate の CPU 検証は **19 passed**（unit 3 / contracts 5 / golden CPU 3 / scene CPU 8）、0 failed、golden 1 ignored、GPU tests 17 filtered。ignored / filtered は GPU 成功として数えない。
- 採用 regression は **10 passed**。fixture は 15 entries / 9 解析的 scenes、同梱素材 28,012 bytes を検証。固定 Noto font の offline hash 検証も成功。
- backlog check は 60 tasks。ADR-0038 の本文決定は変更せず status のみ更新した。ADR template `0000-template.md`、`Cargo.lock` と CPU oracle 実装は変更していない。

## Supervisor の host 検証

Apple M1 MacBook Pro（MacBookPro17,1、16 GiB）、選択 adapter Apple M1 / Metal / IntegratedGpu、macOS 27.0（build 26A428）、Rust / Cargo 1.95.0、wgpu 30.0.1。Metal driver の個別版は OS が返さず、macOS build とその事実を provenance に保存した。

supervisor が QA-003 実装を `cb7c7bbc6dc329de8a4edd5deee108998aacb410` にコミットし、別 worker の STORE-002 / CLI-002 を統合した。基準生成時の clean HEAD は `96babb20c76c19d2dd12e8fe7d4ad8391ca3ea59`。`git status --porcelain --untracked-files=all` が空であることを確認して生成・採用した。worker はコミット・統合作業を行っていない。

host 手順（リポジトリ root。出力先は実際の run を記載）:

```sh
unset KRONELLO_GOLDEN_UPDATE
export KRONELLO_GOLDEN_OUTPUT="$PWD/target/golden/run.qa003.39KJng"
WGPU_BACKEND=metal KRONELLO_GOLDEN=1 KRONELLO_GOLDEN_UPDATE=1 \
  cargo test -p kronello-gpu --test golden --locked -- --ignored --nocapture
python3 scripts/golden_adopt.py "$KRONELLO_GOLDEN_OUTPUT/candidate" \
  > "$KRONELLO_GOLDEN_OUTPUT/adoption.log"
unset KRONELLO_GOLDEN_UPDATE
export KRONELLO_GOLDEN_OUTPUT="$PWD/target/golden/run.qa003.compare.9VEBWh"
WGPU_BACKEND=metal KRONELLO_GOLDEN=1 \
  cargo test -p kronello-gpu --test golden --locked -- --ignored --nocapture
```

上記の run は既に生成済みであり再利用しない。再実行には [比較手順](golden-comparison.md) の `mktemp` で新規 directory を用意する。採用を再実行する場合はその時点の clean HEAD で候補を生成し直す。

| 段階 | supervisor の実行結果 / artifact |
|---|---|
| UPDATE | exit 0、**1 passed**、21 scenes / 21 frames、全画素 CPU oracle validated、`candidate_may_be_adopted=true`、`status=candidate-only; no baseline comparison`。`target/golden/run.qa003.39KJng/report.json` |
| 明示採用 | exit 0、`status=adopted`、revision は上記 clean HEAD、21 scenes。`target/golden/run.qa003.39KJng/adoption.log` |
| 通常比較 | exit 0、**1 passed**、`status=pass`、21 scenes / 21 frames、全シーン `mismatched_pixels=0`。`target/golden/run.qa003.compare.9VEBWh/report.json`、stdout は `target/golden/run.qa003.compare.9VEBWh.stdout` |
| 基準のコミット | supervisor が `507c3e28dea255ddc44a60fb2188cf7ca85d91ff` に 47 新規ファイルを登録。生成 revision は基準 provenance に保持 |

比較レポートの最大 RGB error は **0.00011500716209411621**（`srgb-output-roundtrip` の decoded working 値と保存 binary16 の差）、最大 alpha error は **0**。許容誤差を変更せず、エッジを除外せず全 6,870 pixels が合格した。登録直後の比較の dirty 状態は採用した baseline の未追跡ファイルを provenance として記録したもので、候補生成時の provenance は clean。

supervisor は生成前の統合 revision `96babb20c76c19d2dd12e8fe7d4ad8391ca3ea59` について、host workspace 全体の fmt / clippy / backlog 成功と **317 tests passed、0 failed** も報告した。この集計は supervisor 提供の host 結果であり、worker が実行した上記 264 件とは別。追加の workspace run のコマンド詳細・個別ログは handoff に含まれないため、本記録の直接確認可能な GPU 証拠は UPDATE / compare の report と基準 artifact とする。

## サイズと artifact の再確認

採用ログと worker の read-only 再集計は一致した。

| 項目 | byte 数 | 上限 |
|---|---:|---:|
| candidate（47 ファイル、adoption manifest を含む） | 158,426 | 同梱合計に算入 |
| `tests/fixtures/` + `tests/golden/` 全ファイル | 209,109 | 1,048,576（1 MiB） |
| 最大ファイル（scene manifest） | 73,120 | 262,144（256 KiB） |

ファイルの実 byte 数で比較し、filesystem の block 単位の使用量（supervisor が報告した baseline directory の 308K）とは区別した。21 シーンは調整・分割なしで上限内に収まる。

worker は登録済みの 46 hashed artifacts を SHA-256 / byte 数で再検証し、host candidate と byte 一致すること、21 RGBA16F の長さ・全画素の有限値・alpha 契約、report の全シーン合格と数、生成 revision / clean 状態を読み取りで確認した。GPU を worker sandbox で再実行した結果ではない。
